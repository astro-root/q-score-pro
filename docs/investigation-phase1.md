## 3. UI/UXの問題(コードから確認)
1. **ナビゲーションが無い**: `/tournaments/...` へのリンクは全体で数カ所のみ。参加者・ラウンド・エントリー・レイアウト等は URL を知らないと到達できなかった。
2. **大会トップに「Phase 2以降で実装予定」の古い文言**が残っていた。
3. **スタイルが二系統**: ダークのデザイントークンと、ハードコードの slate/indigo が混在。共通UI(Card/Button 等)を import している箇所は 2 つだけ(約30ファイルがハードコード色)。
4. 認証画面は `AuthShell` を作っていたが login/signup は使っていなかった。
5. 得点操作画面が一般管理画面と同じシェルの中にある(専用の全画面設計になっていない)。

## 4. データモデル・権限の問題
- 単一ロール(`tournament_members.role` が enum 1つ)。複数ロール化には列の配列化または `member_roles` 表が必要。DB(RLS関数 `has_tournament_role` 等)・`can()`・API を同時に直す必要がある。
- `rounds` のルール適用単位(大会/Round/Set/Group)の階層が不明確。`groups` は `round_participants` 上の値で、独立エンティティではない。
- 問題・解答を公開ページから隠す RLS は、`questions` 導入時に新規設計が必要。
